How Client-Side WebGPU & WebAssembly Neural Text-to-Speech Works

An inside look at the PureTTS architecture: executing an 82-million-parameter neural speech synthesis model directly inside a browser Web Worker with zero cloud servers.

1. Why Traditional Cloud TTS Services Have Strict Character Paywalls

For the past decade, high-fidelity neural text-to-speech required massive server-side data center GPUs (such as NVIDIA A100 or H100 clusters). Every time a user clicked "Generate" on a traditional cloud TTS website, their text was sent over an HTTPS API to a remote GPU cluster, synthesized into an audio file, stored in cloud object storage, and streamed back to the browser.

Because cloud GPU compute costs money for every second of inference, cloud TTS providers must enforce strict character limits (often 10,000 characters per month on free tiers), require account sign-ups to prevent abuse, and charge $5 to $99+ per month for longer documents. Worse yet, every confidential document or personal script must be uploaded to third-party servers.

PureTTS eliminates the server entirely. By combining two breakthrough web standards—WebGPU and SIMD WebAssembly (WASM)—with the compact, high-efficiency Kokoro-82M neural model, PureTTS shifts 100% of the compute to the processor already sitting on your desk or in your pocket.

2. Inside the Kokoro-82M Neural Architecture

One might wonder how an 82-million-parameter model can rival or outperform text-to-speech models that are 10x larger. The answer lies in the architectural efficiency of Kokoro-82M v1.0 (built upon a streamlined StyleTTS 2 and ISTFTNet decoder design):

  • Decoupled Acoustic & Prosody Modeling: Rather than using a monolithic autoregressive transformer that slowly predicts one audio token at a time, Kokoro uses a lightweight phoneme encoder, a duration predictor, and style diffusion vectors that map phoneme sequences directly to acoustic features in parallel.
  • ISTFTNet Vocoder (Inverse Short-Time Fourier Transform): Traditional neural vocoders (like WaveNet or full HiFi-GAN) spend enormous compute generating raw time-domain samples at 24,000 Hz. By predicting magnitude and phase spectrograms and using a deterministic Inverse STFT layer for the final waveform reconstruction, Kokoro achieves studio-clarity 24kHz audio at a fraction of the floating-point operations (FLOPs).
  • Expressive Style Vectors: Each of the 10 American and British voices in PureTTS is represented as a compact acoustic style embedding vector that modulates pitch contour, timbre, and cadence across varying sentence lengths.

3. The 4-Stage In-Browser Synthesis Pipeline

When you click Convert Text to Speech in PureTTS, all execution happens asynchronously inside an isolated browser Web Worker (`tts-worker.js`) so the main UI thread stays 100% responsive:

Stage 1: Intelligent Sentence Segmentation & Normalization

Long documents (such as 50-page PDFs or full audiobook chapters) are cleaned to repair line-break hyphens and segmented into natural prosodic chunks of ~250–400 characters along punctuation boundaries. This bounds peak RAM usage regardless of whether your input is 100 words or 100,000 words.

Stage 2: Grapheme-to-Phoneme (G2P) Tokenization

Each sentence is converted from English spelling (graphemes) into International Phonetic Alphabet (IPA) phoneme tokens with primary and secondary lexical stress markers. Context-aware rules resolve heteronyms (such as "read" present tense vs. "read" past tense) before tokenization.

Stage 3: ONNX Runtime Web Inference (WebGPU vs. WASM)

The phoneme tensor and the selected voice's style embedding are fed into ONNX Runtime Web (`@huggingface/transformers` + `ort-web`). Depending on your device hardware and selected engine mode, the neural network executes either via WGSL compute shaders on your GPU (WebGPU) or multi-threaded 128-bit SIMD instructions on your CPU (WebAssembly).

Stage 4: Real-Time Streaming & 24kHz PCM WAV Concatenation

As each sentence chunk finishes inference, its 32-bit floating-point audio array is immediately dispatched to the main thread for optional real-time playback (`AudioContext`) and combined into a lossless, 24,000 Hz 16-bit PCM `.wav` file ready for one-click download.

4. WebGPU (FP32) vs. WebAssembly (Quantized q8) Comparison

Different devices have vastly different memory ceilings and graphics capabilities. A desktop workstation with a dedicated GPU handles unquantized 32-bit floating-point tensors effortlessly, whereas mobile browsers on iOS and Android impose strict per-tab memory limits.
